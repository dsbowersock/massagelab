Source lock: `fa78ca01a42179329cc223df77c76f308e76320b`; source inspection: 2026-09-06. This inventory records code contracts without inspecting any user's browser storage, records, cookies or credentials. It plans Phase 8; it does not implement migration or clear data.

Authority: [charter](atmoshaper-migration-charter.md), [domain recovery plan](atmoshaper-domain-cutover-plan.md), source `docs/wiki/privacy-first-data-architecture.md`, `docs/wiki/privacy-and-phi.md` and `docs/wiki/pwa-offline-strategy.md`.

## Migration rules

- **P — preserve:** keep the current key, value/schema validation and reader/writer behavior during bootstrap. Origins remain separate. Rehydrate only through already-authorized, sanitized account-preference behavior or a later explicit user-controlled mechanism; no automatic cross-origin copy is approved.
- **L — legacy:** preserve valid legacy reads and conservative handling of malformed/older encrypted inputs. Current successful same-origin migration behavior remains unchanged for parity; it is not permission to add new deletion during repository/domain migration.
- **C — credential:** sign in or restart the flow on the new origin. Never copy cookies, OAuth state, binding tokens, room/device proofs or credentials through URLs, local/session storage, messages or migration exports.
- **X — sensitive local transfer:** unlock on the original origin, export an encrypted user-controlled bundle, then explicitly select/import it on the new origin. Never automatically upload, postMessage, synchronize or relay PHI or encrypted-vault content across origins. Preserve plaintext-output warnings.
- **S — service worker/PWA:** retain the original install and recovery paths; test upgrades and offline recovery. Cache changes need a scoped, non-destructive later design.
- **U — unresolved:** retain unknown state and finish inventory before dependent cutover. A missing source hit is not proof that an old install has no such data.

Every row's cleanup prohibition applies to this migration. Existing explicit user-delete controls, expiry or validated migration cleanup remain source behavior and are not invoked or expanded by this work. Placeholders such as `<owner>`, `<room code>` and `<manifest>` describe key construction, never captured values.

## PWA transition hazards and required proof

Source `public/sw.js:43-52` currently deletes **every Cache Storage name except its current cache** on activation. That is observed existing behavior, not a new recommendation. A future old-origin recovery cache or another app-owned cache could be removed by that activation path. Preserve source parity now; Phase 8 must establish and test scoped cache ownership before adding a recovery cache or changing worker identity. Never run `localStorage.clear()`, `sessionStorage.clear()`, blanket IndexedDB deletion, bulk cache deletion or automatic uninstall/unregister as migration cleanup.

The current public route allowlist is `/`, `/notes`, its four local record tools, `/chimer`, `/clock` and `/anatomime`. The SW warms anonymous documents with credentials omitted, does not cache live signed-in navigations, and restricts runtime caching to static assets/offline HTML. Account, admin, auth, API, pricing, calendar, booking and other non-allowlisted routes remain online-only. Clinical records remain in their local encrypted owner, never SW response caches.

Source manifest identity is MassageLab with standalone display and 192/512 ordinary and maskable PNG icons. The `/` manifest id is relative to origin; do not promise old installation continuity across domains. Keep existing working icons until approved replacement assets and separate visual verification exist.

Phase 8 proof must cover both `massagelab.app` and `www.massagelab.app`, a new-origin installation, and old installed-PWA launches. Use synthetic records only. Verify:

1. Existing unlocked/locked vault behavior, valid legacy plaintext migration, older encrypted intake, malformed input retention, wrong passphrase handling and encrypted export/import round trip.
2. No automatic PHI/vault transfer or clinical network upload; account preference projection continues rejecting clinical fields and preserves account-owner isolation.
3. Separate sign-in, Google callback/binding, TOTP enrollment and Calendar state behavior on each origin without credential forwarding.
4. Donation/background return recovery without automatic provider retry, duplicate payment or silent attempt migration.
5. Existing favorite/background/timer/mixer/study/business preferences remain readable on old origin; explicit new-origin behavior is explained.
6. Old installed PWA updates online, launches offline, reaches recovery after returning online, and retains encrypted local records. Prove cache ownership before retirement.
7. Actual cookies, local/session keys, IndexedDB databases and Cache Storage names in approved synthetic browser contexts; record names/counts only, never payloads.
8. Legacy valid imports continue to pass before any AtmoShaper-facing filename is emitted. No old origin or import format is retired without the recovery-period decision.
