## Work that is not an approved refactor

Service-worker cache ownership needs a Phase 8 transition design because source activation deletes all non-current caches; changing that behavior is not an unreviewed parity-preserving extraction. Google Calendar display-name changes can change calendar discovery/creation and require Phase 9 provider compatibility evidence. Dependency removal, generated-asset deletion, schema cleanup, auth-attempt retirement, logo changes and legal text changes belong to separate phase/authority boundaries.

There is no evidence-backed target yet for a general error-handling framework. Do not add one based solely on repeated catch blocks. Capture a concrete observable inconsistency and its privacy/provider boundary first.

## Candidate acceptance and verification

For a future candidate, record exact source/head, one observable problem, old/new owner boundary, focused regression oracles, route/visual/provider/privacy invariants, before/after measurements, and the old path's keep/retire status. Run the existing full typecheck/lint/unit/build and affected browser gates after focused proof. An unexpected behavior, provider-call, accessibility, layout, import-format or privacy change stops the refactor; it must not be accepted by updating parity snapshots.

All source sizes above are line counts from committed blobs, not measured complexity scores or benchmark improvements. Task 2 ran no runtime or performance tests and changed no implementation.
